## 第一天和第二天 学习记录统计器



支持添加学习主题和分钟数、查看记录、统计记录数量、累计时长和各主题时长。拒绝空主题和非正整数分钟数。



| 菜单输入 | 功能 |

| --- | --- |

| 1 | 添加记录 |

| 2 | 查看记录 |

| 3 | 查看统计 |

| 4 | 保存记录，仅第二天提供 |

| 0 | 退出 |



第二天版本选择 `4` 后，将全部记录保存到 `day02/main.py` 同目录的 `learning_records.json`。退出不会自动保存；启动时自动读取历史记录。



记录采用列表中嵌套字典的格式，每条记录只有一组键值对：主题为非空字符串，分钟数为正整数。



```json

[

    {"Python": 45},

    {"Git": 30}

]

```



文件不存在时，以空列表开始。JSON 损坏、结构错误或其他读取失败时，报错并停止启动，先检查或备份原文件。保存失败时提示原因。



验证示例：添加 Python 45、Git 30、Python 60，保存并重启后应仍有 3 条、135 分钟；Python 累计 105 分钟，Git 累计 30 分钟。

## 第四天 DeepSeek 单轮问答

在 PyCharm 中进入 Run → Edit Configurations，选择实际运行脚本的配置；运行当前版本时，脚本路径应指向 `day06/main.py`，解释器应选择已安装依赖的环境。在 Environment variables 中添加：



| 名称 | 值 |

| --- | --- |

| DEEPSEEK_API_KEY | `<你的 DeepSeek API Key>`，占位说明，不是真实密钥 |

不要把真实密钥写进代码、README、截图或 Git 提交。



### 行为与错误处理



程序每次运行接收一个问题，调用一次模型，打印回答后结束；同时显示调用耗时，以及接口提供的输入、输出和总 token 数。未提供用量时明确提示，不自行估算。



- 空问题：提示后结束，不调用模型。

- 密钥未设置或为空：提示“配置缺失”，不创建客户端。

- 超时、网络连接失败、鉴权失败：分别提示。

- 其他 HTTP 错误：显示状态码及错误详情，便于区分余额、参数或模型配置问题。

- 回答为 None、空字符串或纯空格：提示未返回有效回答。



示例问题：“请用两句话解释 Python 字典。”回答由模型生成，不要求每次完全一致。



遇到过的问题：创建客户端时报 Missing credentials，原因是实际运行配置没有提供 `DEEPSEEK_API_KEY`；将环境变量添加到第四天使用的运行配置后解决。



第四天版本保留单轮问答；第五、六天的连续对话见下文。模型调用可能产生费用，以服务商当前规则为准。



## 第五天和第六天 连续对话助手



运行 `pyproject/day06/main.py` 后直接输入问题，程序每次携带当前保留的历史。回答成功后形成完整问答；失败时移除本次问题，提示错误并继续等待输入，不把错误提示保存成模型回答。



### 支持的命令



| 输入 | 行为 |

| --- | --- |

| 普通问题 | 请求模型、打印有效回答、更新历史 |

| 空输入或纯空格 | 提示不能为空，继续等待，不请求模型 |

| `/help` | 显示使用说明，第六天版本提供 |

| `/clear` | 清空用户和助手历史，保留系统要求 |

| `/save` | 将当前保留的消息列表保存为 JSON |

| `/exit` | 退出程序，不自动保存 |



命令由程序处理，不发给模型，也不加入历史。



### 历史规则与保存位置



- 完成一轮后最多保留最近五轮完整问答，加上系统消息共 11 条。继续请求时还会加入本次新问题。

- 超过上限时，成对移除最早的问题与回答，保留系统消息。按轮数限制不等于严格限制 token。

- `/save` 写入实际运行的 `main.py` 同目录下的 `chat_history.json`，采用 UTF-8，中文直接显示，保存时覆盖该文件。

- 保存的是当前保留的历史，包含系统消息；已裁剪的早期问答不在文件中。

- 退出不会自动保存，启动也不会自动恢复已保存的聊天。

- `/clear` 只重置内存历史，不删除已有文件；清空后再次保存，会覆盖旧文件。



### 错误与当前限制



已处理密钥缺失或为空、请求超时、网络连接失败、鉴权失败、其他 HTTP 错误，以及空回答。HTTP 错误提示包含状态码和错误消息，便于检查余额、参数和模型配置。保存失败时输出文件错误并继续运行。



当前尚未完整验证所有异常响应结构，例如 `choices` 为空的情况；没有增加自定义的输入 token 预算、摘要记忆、流式显示或自动恢复功能。第六天当前未输出每轮耗时，模型请求仍设置 60 秒超时，并保留接口提供的 token 用量显示。

## 第八天 本地资料问答



本阶段把本地文本读入、切成带来源的片段，再根据人工选定的片段回答问题。当前尚未接入 embedding、向量数据库或自动相似度检索。



### 资料与切分结果



练习资料位于 `pyproject/day08/docs/`，均为 UTF-8 文本：



| 文件 | 字符数 | 片段数 |

| --- | ---: | ---: |

| 使用说明.txt | 286 | 1 |

| 项目介绍.txt | 304 | 1 |

| 学习笔记.txt | 1369 | 5 |

| 合计 | 1959 | 7 |



当前规则为每块最多 400 个 Python 字符串字符，相邻块重叠 80 字符，起点每次前进 320。末块不足 400 字符也保留；一块到达正文末尾后结束，不生成空块或多余重复尾块。此处不是按 UTF-8 字节或模型 token 计数。



例如，850 字符正文分成 400、400、210 三块；重叠用于保留边界附近的上下文，固定字符切分仍可能截断句子。



`document_loader.py` 遍历 txt 文件，跳过读取失败或只有空白的正文，生成片段列表后一次保存到 `pyproject/day08/data/chunks.json`。JSON 使用 UTF-8，中文直接显示并有缩进。每条记录包含：



| 字段 | 含义 |

| --- | --- |

| source | 带后缀的来源文件名 |

| chunk_id | 文件名与文件内从 1 开始的序号，例如 学习笔记.txt#2 |

| text | 当前片段的正文 |



### 运行方式



使用前文的 `intershipcheck` 环境和 `openai==3.37.0`，在实际运行第八天脚本的环境或 PyCharm 配置中设置 `DEEPSEEK_API_KEY`。以下命令在 `study` 目录执行：



```bash

```



当前生成程序要求 `pyproject/day08/data/` 已存在；首次运行时先建立该目录。修改 docs 中的资料后，重新运行生成程序，再启动问答入口。



`main.py` 中通过 `SELECTED_CHUNK_ID = "学习笔记.txt#2"` 人工指定参考片段。需要换资料时修改这个编号，并确认它存在于最新 JSON 中。



运行入口后直接输入问题，例如：



```text

读取多个文档时，如果其中一个文件只有空白内容，程序会怎样处理？
```

### 运行与重新生成

```bash

```



生成入口递归读取脚本同目录 `docs/` 下的 `.txt` 文件，并排序后逐份处理。输入和输出位置以脚本所在目录为基准。修改资料后重新运行生成入口，会覆盖 `pyproject/day09/data/chunks.json`。保存前使用 `path_save.parent.mkdir(parents=True, exist_ok=True)` 创建缺失的输出目录；目录已有时可以继续运行。



`load()` 读取 UTF-8 正文；`process_document(content, source, chunks_size=400, overlap=80)` 返回一份文档的片段列表；`main()` 汇总所有文档，统一保存。读取失败或正文为空时，该文档处理结果为空列表，其他文件继续处理。题型统计入口单独读取 `evaluation/questions.json`。



### 分块规则



- 按两个连续换行 `\n\n` 识别段落，过滤纯空白段；段落内部的单个换行保留。

- 有效原文段落从 1 开始编号。相邻短段落用两个换行连接，合并后的总字符数包含这两个换行，不能超过片段上限。

- 单段自身超过上限时，先保存此前积攒的短段落，再单独切分该长段落。拆出的各块都保留同一个原文段落编号。

- 默认上限为 400 字符、长段落重叠 80 字符，滑动步长为 320。普通段落合并边界不强制增加重叠。

- 最后不足上限的内容保留，到达正文末尾即停止。字符数使用 Python 字符串长度，不是字节数或 token 数。

- 长度参数必须大于 0，重叠参数必须满足 `0 <= overlap < chunks_size`，不符合时抛出 `ValueError`。

- 两个处理函数均支持自定义参数；批量生成入口当前明确使用 `400, 80`，作为检查和题目引用的基准。

| 字段 | 含义 |

|---|---|

## 第十八天 模型工具调用与学习记录查询

在 `pyproject/day18/` 使用 DeepSeek、OpenAI Python SDK 和 PyMySQL，让模型根据问题选择查询主题记录或统计学习时长。`tool_schemas.py` 保存工具说明，`test_tools.py` 负责模型调用、数据库查询和结果回传。运行需要本机 `learning_db.study_records`、已安装的 `openai` 和 `PyMySQL`，以及当前运行环境中的 `DB_USER`、`DB_PASSWORD` 和 `DEEPSEEK_API_KEY`。

流程：用户提问 → 模型选择工具 → Python 查询 MySQL → 将工具结果加入消息 → 再次请求模型生成回答。

### 工具调用知识点

- `tools=tools`：把工具说明传给模型；左边是接口参数名，右边是自己的工具列表。模型提出工具调用，Python 程序才实际执行函数。
- `message.tool_calls` 是工具调用列表；先判断是否存在，再遍历各项。`.function.name` 是工具名称，`.function.arguments` 是 JSON 参数字符串，`.id` 是本次调用编号。
- `json.loads()` 将参数字符串转换为 Python 数据；解析失败可处理 `json.JSONDecodeError`。查询主题前检查参数是字典、`topic` 是非空字符串。
- 工具结果消息使用 `role: "tool"`，并以 `tool_call_id` 对应当前工具调用的 `id`。一次请求多个工具时，逐个执行并分别添加结果，完成后再次请求模型。
- 将模型完整回复和工具结果按顺序加入 `messages`；思考模式下保留回复中的 `reasoning_content`。直接回答时不需要执行工具。

### 需要记住的 Python 知识

- `for i in range(3)` 最多循环三次，`i` 依次是 0、1、2；`break` 会提前结束循环。
- `for ... else`：循环正常执行完且没有遇到 `break` 时执行 `else`；执行 `break` 时不执行。这里用于提示达到模型调用次数上限。
- 对象属性用点号访问，列表使用下标；`isinstance()` 可以判断返回值类型，先确认是元组再按长度拆包。
- MySQL 返回的日期可能已经是 `date` 对象；`date.fromisoformat()` 接收日期字符串。`Decimal` 是十进制数，JSON 默认不能直接序列化。
- `json.dump(..., ensure_ascii=False, indent=4)` 保存时使中文直接显示并缩进；`indent` 是参数。

### 已验证与当前限制

已交互验证单主题查询、学习统计、无记录、多轮工具调用、同一条回复中同时查询 Python 和 Git、直接回答，以及调用次数上限提示。工具参数无效或工具未知时，程序提示并结束；这些错误分支尚未模拟测试。查询失败与空结果的区分暂未补充。模型生成的回答仍需核对；多主题测试中曾出现 Git 记录日期写错的情况。模型接口调用可能产生费用。
