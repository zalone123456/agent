# 第九天问答评估题

准备日期：2026-10-28。共 20 题：12 道单文档题、4 道多文档题、4 道资料不足题。`questions.json` 顶层是列表。

## 数据范围

题目只依据当前 `docs` 中的资料，不依赖外部知识、代码文件或模型猜测。可回答题引用《使用说明》《项目介绍》《学习笔记》，没有把用于切分测试的数字标记当作项目事实。资料不足题已结合全部 5 个文本文件阅读核对，其含义是资料没有写明，不是断言项目没有该功能。

《学习笔记》描述的是第八天实现；相关题目明确限定这一历史范围。不能用其中“不递归查找”等历史描述代替当前 day09 代码的行为。

## 字段

| 字段 | 含义 |
|---|---|
| id | 题目唯一编号，Q01～Q20 |
| type | single_source：单文档；multi_source：多文档；unanswerable：资料不足 |
| answerable | 仅根据资料是否能够回答，布尔值 |
| question | 问题文本 |
| reference_answer | 根据原文整理的参考答案；表达可以不同，但事实应一致 |
| sources | 来源文件和原文段落范围；资料不足题为空列表 |
| chunk_ids | 当前分块结果中对应的片段序号；资料不足题为空列表 |
| evidence | 支撑答案的原文短摘录及所在段落，用于核对 |

段落按空行拆分，过滤纯空白段后从 1 编号。单个换行仍在同一段内。

## 对应分块

当前片段文件为 `day09/data/chunks.json`，基准设置为 400 字符上限、长段落重叠 80 字符，共 11 块。其“序号”字段对应本题集的 `chunk_ids`；“文件名”字段对应 `sources` 中的 `source`。

重新分块后，应核对 `chunk_ids` 是否仍正确。原文段落位置比片段编号更稳定；修改原文后也需要重新检查题目和证据。
