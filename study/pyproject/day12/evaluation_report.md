# 第十二天 RAG 评测记录

## 评测目标

检查文档问答程序能否找到依据、正确回答并引用原文，并比较检索数量 `top_k=3` 与 `top_k=5`。选定配置后，使用留出题单独检查。

## 数据与配置

- 题目：第九天题库 20 题，调试集 12 题，留出集 8 题。
- 文档：使用第十天 Chroma 向量库中的 11 个片段，来源包括项目介绍、使用说明、学习笔记和切分测试材料。
- 分块：按空行拆分并合并较短段落；长段落按最多 400 字符、重叠 80 字符切分。
- 向量模型：`BAAI/bge-m3`，向量维度 1024；距离类型为 L2。
- 对话模型：`deepseek-flash`；每题独立请求，不携带其他题目的聊天历史。
- 版本：使用第十一天问答程序和第十天向量索引。两组对照只调整 `top_k`，其他配置保持一致。
- 测试方法：真实调用向量和对话接口；使用原向量库的临时副本，测试不写入个人问答日志。

两组题目均包含可回答题和资料不足题；多来源问题要求所有必要依据进入检索结果。无答案是指当前索引的资料没有答案，不代表整个项目实际没有这些信息。

## 判断标准

可回答题检查：必要依据是否齐全、回答是否完整正确、引用编号是否存在且原文是否支持结论。资料不足题检查：是否明确说明不足、没有猜测。请求失败单独记录，不算正确拒答。耗时由测试脚本测量，包含运行主流程和少量测试封装，不含人工输入等待。

## 调试集基线和对照

调试集包含 9 道可回答题和 3 道资料不足题。同一组题目分别运行 `top_k=3` 和 `top_k=5`：

| 检查项 | top-k=3 | top-k=5 |
| --- | ---: | ---: |
| 可回答题依据齐全 | 9/9 | 9/9 |
| 可回答题回答正确 | 9/9 | 9/9 |
| 可回答题引用有效且有依据 | 9/9 | 9/9 |
| 无答案处理正确 | 3/3 | 3/3 |
| 运行失败 | 0/12 | 0/12 |
| 平均耗时 | 5.05 秒 | 4.39 秒 |

两组都找到了本批题目的必要依据，未发现增加到 5 条带来更多必需依据。Q11 的必要依据两次均排在第 3 位；`top_k=5` 时额外返回的第 4 条也被用于支持切分规则。两组各题只运行一次，平均耗时有波动，不能据此判断哪个配置更快，也没有统计具体 token 用量。

调试集结果相同，因此暂时选择 `top_k=3`，用更少的片段完成后续检查。

## 留出集结果

留出集包含 7 道可回答题和 1 道资料不足题，使用选定的 `top_k=3`，结果与调试集分开统计：

| 检查项 | 结果 |
| --- | ---: |
| 运行成功 | 8/8 |
| 可回答题必要依据齐全 | 4/7 |
| 可回答题回答完整正确 | 4/7 |
| 可回答题引用完整有效 | 4/7 |
| 无答案处理正确 | 1/1 |
| 平均耗时 | 5.34 秒 |

Q18 在当前索引资料中没有 embedding 模型名称和维度，模型明确表示资料不足，没有猜测。项目实际使用的模型配置不能当成被检索资料已经提供的答案。

## 失败案例与排查

### Q10 分块上限、重叠和单位

题库指定的 `学习笔记.txt#2` 没有进入前 3 条。模型给出了正确数字和字符单位，但没有补充“不是 UTF-8 字节数或 token 数”；它引用的 `学习笔记.txt#3` 是一个具体分块示例，不能单独证明一般性的 400 字符上限。检索结果中的测试材料提到上限，但回答没有引用它们。

### Q12 资料不足与来源核对

必要依据 `学习笔记.txt#4` 没有进入前 3 条。模型表示没有找到相关规则，却引用了切分测试材料来讨论正文核对，这些材料不能支持题目所问的结论。原始资料实际上有答案，应归为检索未命中，而非整个知识库无答案。

### Q16 保存记录与读取返回 None

使用说明进入了前 3 条，模型正确回答了保存文件及系统消息；但 `学习笔记.txt#2` 没有进入结果，模型对 `None` 和 `strip()` 部分表示资料不足。它没有编造，但回答不完整，属于多来源题依据不全。

## 结论与局限

本次调试集中，`top_k=3` 和 `top_k=5` 的通过数相同；当前保留 `top_k=3`。留出集暴露了检索未命中、依据不全及引用不能支持结论等问题，说明程序还需要改进。

本次每题只运行一次、题目数量较少，结果不能代表整体准确率。后续可以排查检索排序和测试材料的干扰；如果用本次留出题反复调参，这些题就转为调试题，需要另外准备新的留出题验证。
